## Индексы: зачем нужны и как работают

**Часть:** Производительность и оптимизация · **Модуль:** Индексы и планы выполнения

Практика: **PostgreSQL** (psql или pgAdmin).

### Цели урока

- Объяснить роль индексов при поиске данных
- Создать B-tree индекс
- Измерить влияние индекса на INSERT/SELECT

### Краткая теория

**Индекс** — дополнительная структура данных, ускоряющая поиск по условию за счёт упорядоченного доступа. Без индекса PostgreSQL часто выполняет **Seq Scan** — читает всю таблицу.

#### Аналогия

Таблица — книга без оглавления; индекс — алфавитный указатель: не нужно листать каждую страницу.

#### B-tree (по умолчанию)

```sql
CREATE INDEX idx_employee_email ON employee (email);

EXPLAIN SELECT * FROM employee WHERE email = 'ivan@uni.ru';
-- Index Scan using idx_employee_email
```

B-tree поддерживает: `=`, `<`, `>`, `BETWEEN`, `IN`, `IS NULL` (частично), префикс `LIKE 'abc%'`.

#### Создание и удаление

```sql
CREATE INDEX CONCURRENTLY idx_salary ON employee (salary);
DROP INDEX idx_salary;
```

`CONCURRENTLY` — без длительной блокировки записи (дольше строится).

#### Цена индексов

| Плюсы | Минусы |
|-------|--------|
| Быстрый SELECT по ключу | Замедление INSERT/UPDATE/DELETE |
| Ускорение JOIN и ORDER BY | Дополнительное место на диске |
| UNIQUE — целостность | Нужно обслуживать (VACUUM, REINDEX) |

**Правило:** индексируйте столбцы в **WHERE**, **JOIN**, **ORDER BY** частых запросов; не создавайте «на всякий случай» на каждый столбец.

#### Просмотр индексов

```sql
\d employee
SELECT indexname, indexdef FROM pg_indexes WHERE tablename = 'employee';
```

#### Когда индекс не используется

- Функция на столбце: `WHERE lower(email) = 'x'` — нужен индекс на `lower(email)`
- Низкая селективность (мало уникальных значений) — планировщик выберет Seq Scan
- Маленькая таблица — seq scan дешевле
