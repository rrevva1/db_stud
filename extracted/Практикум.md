PostgreSQL – это мощная, открытая реляционная система управления базами данных (СУБД), которая обеспечивает надежное хранение и эффективный доступ к данным. Созданная на основе многолетнего опыта сообщества разработчиков, PostgreSQL представляет собой гибкую и расширяемую платформу, обладающую множеством функциональных возможностей. Данная СУБД имеет открытую лицензию, которая предполагает свободное использование, модификацию и распространение как в коммерческих, так и в некоммерческих проектах. Запрос на создание таблицы создает пустую таблицу. Она располагается в базе данных, в которой выполняется запрос, если не указано иного. Принадлежность таблицы определяется пользователем, который выполнил этот запрос. В данном случае таблица будет создана в схеме по-умолчанию или public. Для выбора иной схемы расположения следует ее создать перед созданием таблицы, а в запросе CREATE TABLE указать целевую схему через точку «scheme.tablename».

||Имя создаваемой таблицы должно отличаться от имени создаваемых таблиц в текущей схеме, причем PostgreSQL не учитывает разницы между регистрами символов и имя table_name TaBlE_NAme считаются как идентичные. При создании таблицы допустимо указывать ограничения, накладываемые на поля данных. Под ограничением следует понимать некоторый набор допустимых значений, нарушать границы которого данные в имеющейся таблице не могут. Например, если в таблице хранится температура, то целесообразно наложить ограничение на значение т.к. t > – 273 С. ## Описание выполнения работы

PostgreSQL предоставляет множество встроенных типов данных, которые доступны по умолчанию для пользователей. Это означает, что СУБД предоставляет широкий набор типов, с которыми можно работать. Кроме того существует возможность пользователю самому создавать собственные типы данных. Подобные возможности стали популярны у разработчиков и администраторов баз данных. За более детальной информацией по типам данных СУБД PostgreSQL можно обратиться на оффичиальную страницу документации <u>postgresql.org/docs/current/datatype.html</u>. В настоящей практической работе рассматриваются целочисленные числовые типы, числа фиксированной точности, типы данных с плавающей точкой, последовательные типы (serial). В PostgreSQL есть несколько типов данных для целых чисел: smallint, integer и bigint: -smallint представляет целые числа со знаком от -32768 до 32767; -integer представляет целые числа со знаком от -2147483648 до 2147483647; -bigint представляет целые числа со знаком от -9223372036854775808 до 9223372036854775807. Эти типы данных различаются по размеру и диапазону значений, которые они могут хранить. smallint занимает 2 байта, integer - 4 байта, а bigint - 8 байт. Например, если вам нужно хранить целые числа в диапазоне от -100 до 100, вы можете использовать тип данных smallint. Если вам нужно хранить более

широкий диапазон значений, вы можете использовать тип данных integer или bigint в зависимости от требуемого размера и диапазона. Ниже представлена сводная таблица по числовым типам данных [2].

Тип данных numeric, представляет числа фиксированной точности. Этот тип позволяет хранить числа с фиксированным количеством десятичных знаков при выполнении математических операций. Тип данных numeric имеет два параметра: precision (точность) и scale (масштаб). Параметр precision указывает общее количество цифр (включая цифры до и после десятичной точки), которые

могут быть сохранены в числе, а параметр scale указывает количество десятичных знаков. Например, если у вас есть числовое значение с параметрами numeric(6, 2), это означает, что число может иметь общую длину до 6 цифр, включая 2 десятичных знака. Numeric в PostgreSQL обеспечивает вычисления с фиксированной точностью, что может быть полезно при работе с финансовыми данными, где точность вычислений имеет значение. Типы данных с плавающей точкой: -float - тип данных одинарной точности. Он занимает 4 байта и может хранить числа с точностью до 6 десятичных знаков. -double -тип данных двойной точности. Он занимает 8 байт и может хранить числа с точностью до 15 десятичных знаков. -real - синоним для типа данных float. Например, если нужно хранить числа с плавающей точкой с большей точностью, вы можете использовать тип данных double или numeric. Если же нужна меньшая точность, то можно использовать float. Кроме того, эти типы поддерживают значения бесконечности Infinity, -Infinity (отрицательная бесконечность) и NaN (не число). Последовательные типы данных предоставляют автоматически генерируемые последовательности чисел при вставке новых записей в таблицу. Эти типы данных включают: -serial - это псевдоним для типа данных integer. При вставке новой записи в таблицу с полем типа serial, PostgreSQL автоматически генерирует уникальное целое число для этого поля. Диапазон значений для serial составляет от 1 до 2147483647; -bigserial - это псевдоним для типа данных bigint. При вставке новой записи в таблицу с полем типа bigserial, PostgreSQL автоматически генерирует уникальное целое число для этого поля. Диапазон значений для bigserial составляет от 1 до 9223372036854775807; -smallserial - это псевдоним для типа данных smallint с автогенерацией значения при вставке. Диапазон значений для smallserial составляет от 1 до 32767. Эти типы данных полезны, когда нужно автоматически генерировать уникальные идентификаторы для записей в таблице.

## Внешний ключ

Внешний ключ (Foreign Key) в базах данных используется для связи двух таблиц между собой. Он определяет отношение между столбцами в одной таблице (дочерней таблице) и столбцами в другой таблице (родительской таблице). Внешний ключ обеспечивает целостность данных и поддерживает связи между таблицами. Основные характеристики внешнего ключа: -связь между таблицами: Внешний ключ определяет связь между столбцами в дочерней таблице и столбцами в родительской таблице. Значение внешнего ключа в дочерней таблице обычно ссылается на значение первичного ключа в родительской таблице. -ограничение ссылочной целостности: Внешний ключ обеспечивает ссылочную целостность данных, что означает, что значения внешнего ключа в дочерней таблице должны ссылаться на существующие значения первичного ключа в родительской таблице.

-операции ON DELETE и ON UPDATE: Внешний ключ может быть настроен с операциями ON DELETE и ON UPDATE, которые определяют, что происходит с связанными записями в дочерней таблице при удалении или обновлении записей в родительской таблице. Пример использования внешнего ключа при создании таблицы:

Листинг 42. Пример внешнего ключа CREATE TABLE orders ( order_id SERIAL PRIMARY KEY, customer_id INT, order_date DATE, FOREIGN KEY (customer_id) REFERENCES customers (customer_id) );

В этом примере столбец customer_id в таблице orders является внешним ключом, который ссылается на столбец customer_id в таблице customers.

## Удаление связанных строк

Удаление связанных строк в PostgreSQL может быть выполнено с использованием оператора DELETE и дополнительных условий, таких как ON DELETE CASCADE или ON DELETE SET NULL. При использовании ON DELETE CASCADE, удаление строки из родительской таблицы автоматически приведет к удалению всех связанных строк из дочерней таблицы. Например:

Листинг 43. Пример связного удаления CREATE TABLE orders ( order_id SERIAL PRIMARY KEY, customer_id INT, order_date DATE, FOREIGN KEY (customer_id) REFERENCES customers (customer_id) ON DELETE CASCADE );

В этом примере, если строка с определенным customer_id в таблице customers будет удалена, все связанные строки в таблице orders с тем же customer_id также будут удалены.

При использовании ON DELETE SET NULL, удаление строки из родительской таблицы приведет к установке значения внешнего ключа в дочерней таблице в NULL. Например:

Листинг 44. Пример реализации ON DELETE SET NULL CREATE TABLE orders ( order_id SERIAL PRIMARY KEY, customer_id INT, order_date DATE, FOREIGN KEY (customer_id) REFERENCES customers (customer_id) ON DELETE SET NULL );

В этом примере, если строка с определенным customer_id в таблице customers будет удалена, значение customer_id в связанных строках в таблице orders будет установлено в NULL. Вместо использования ON DELETE CASCADE или ON DELETE SET NULL, можно выполнить операцию DELETE с использованием подзапроса, чтобы удалить связанные строки в дочерней таблице. Например:

Листинг 45. Пример удаления с подзапросом DELETE FROM orders WHERE customer_id IN (SELECT customer_id FROM customers WHERE condition);

Здесь строки в таблице orders, связанные с определенными customer_id из таблицы customers, будут удалены на основе определенного условия. Важно отметить, что использование ON DELETE CASCADE или ON DELETE SET NULL должно быть осознанным решением, чтобы избежать нежелательного удаления данных или нарушения целостности данных. В PostgreSQL, использование ON DELETE SET NULL позволяет установить значение внешнего ключа в NULL при удалении строки из родительской таблицы. Это означает, что связанные строки в дочерней таблице не удаляются, но значения внешнего ключа в этих строках устанавливаются в NULL.

Листинг 46. Пример использования ON DELETE SET NULL CREATE TABLE orders ( order_id SERIAL PRIMARY KEY, customer_id INT,

order_date DATE, FOREIGN KEY (customer_id) REFERENCES customers (customer_id) ON DELETE SET NULL );

В этом примере, если строка с определенным customer_id в таблице customers будет удалена, значение customer_id в связанных строках в таблице orders будет установлено в NULL. Подобные ухищрения могут быть полезны, когда жизненный цикл родительской таблицы короче жизненного цикла дочерней таблицы. Например, в системе доставки каждая посылка может быть назначена только одному маршруту. Если маршрут удаляется, то можно установить значение внешнего ключа в NULL для связанных посылок, чтобы сохранить их в базе данных. В PostgreSQL еще поддерживается действие ON DELETE SET DEFAULT. Это означает, что при удалении строки из родительской таблицы, значение внешнего ключа в дочерней таблице будет установлено в его значение по умолчанию.

Листинг 47. Пример использования ON DELETE SET DEFAULT CREATE TABLE orders ( order_id SERIAL PRIMARY KEY, customer_id INT DEFAULT 1, order_date DATE,

FOREIGN KEY (customer_id) REFERENCES customers (customer_id) ON DELETE SET DEFAULT );

Если строка с определенным customer_id в таблице customers будет удалена, значение customer_id в связанных строках в таблице orders будет установлено в его значение по умолчанию, которое в данном случае равно 1. Однако, стоит отметить, что если значение по умолчанию не удовлетворяет ограничению внешнего ключа, операция удаления не будет выполнена. Таким образом, при использовании ON DELETE SET DEFAULT необходимо убедиться, что значение по умолчанию соответствует ограничениям внешнего ключа. Действие ON UPDATE CASCADE позволяет автоматически обновлять значения внешнего ключа в дочерней таблице при изменении соответствующего

значения в родительской таблице. Это помогает поддерживать целостность данных и обеспечивает автоматическое обновление связанных данных.

<u>Листинг 48. Пример использования ON UPDATE CASCADE</u> CREATE TABLE customers ( customer_id SERIAL PRIMARY KEY, customer_name TEXT );

CREATE TABLE orders ( order_id SERIAL PRIMARY KEY, customer_id INT, order_date DATE,

FOREIGN KEY (customer_id) REFERENCES customers (customer_id) ON UPDATE CASCADE <u>);</u>

В этом примере, если customer_id в таблице customers изменится, все связанные строки в таблице orders с тем же customer_id также будут автоматически обновлены. Однако, стоит отметить, что использование ON UPDATE CASCADE требует осторожности. Если внешний ключ используется в большом количестве строк, операция обновления может занять значительное время и ресурсы. Кроме того, если внешний ключ связан с критически важными данными, автоматическое обновление может привести к нежелательным изменениям. В таких случаях может быть предпочтительнее использовать ON UPDATE NO ACTION и контролировать процесс обновления вручную.

Вот некоторые основные аспекты SELECT в PostgreSQL: -SELECT может быть использован с различными операторами, такими как WHERE, JOIN и другими, для фильтрации и объединения данных. -может быть использован с функциями агрегирования, такими как COUNT, SUM, AVG и другими, для вычисления агрегированных значений. -может быть использован с оконными функциями для выполнения вычислений на наборе строк, связанных с текущей строкой. -может быть использован с подзапросами для выполнения сложных запросов. Шаблоны LIKE в PostgreSQL используются для выполнения поиска по текстовым значениям, основываясь на определенных шаблонах или образцах. Они позволяют указать условия, которым должны соответствовать значения столбца, чтобы быть включенными в результат. Шаблоны LIKE используются с оператором WHERE в SQL-запросах для фильтрации строк на основе текстовых шаблонов. Они могут содержать специальные символы для определения шаблонов: -% – соответствует любой последовательности символов (включая пустую последовательность).

-_ (символ нижнего подчеркивания) – соответствует любому одиночному символу. -[] – соответствует любому символу, указанному внутри квадратных скобок. -[^] – соответствует любому символу, не указанному внутри квадратных скобок. Шаблоны LIKE могут быть использованы с оператором ESCAPE для указания символа, который будет использоваться для экранирования специальных символов в шаблоне. Начнем рассмотрение с изучения операций над множествами. Основными в теории множеств принято [3] считать следующие: -объединение множеств A и B (рисунок 37 a) – это операция, которая формирует новое множество, включающее в себя все элементы обоих множеств. Например, если A={3, 5, 7, 12} и B={2, 5, 8, 11, 12, 13}, то объединение A и B будет AB={2, 3, 5, 7, 8, 11, 12, 13}; -вычитание множества B из множества A (рисунок 37 б) – это операция, которая формирует новое множество, включающее в себя те элементы множества A, которые не присутствуют в множестве B. Если взять те же множества A и B, то результатом вычитания B из A будет множество, состоящее из элементов 3 и 7, которые присутствуют в A, но отсутствуют в B; -пересечение множеств A и B (рисунок 37 в) – это операция, которая формирует новое множество, включающее в себя только те элементы, которые присутствуют в обоих множествах. Если взять те же множества A и B, то их пересечение будет состоять только из элементов 5 и 12, которые присутствуют в обоих множествах. Эти операции являются основой для работы с множествами в декартовой алгебре и широко используются в математике и информатике.

Оператор JOIN в SQL используется для объединения данных из двух или более таблиц на основе общего поля между ними. Он позволяет комбинировать столбцы из разных таблиц, создавая новую таблицу в результате объединения. Существуют различные типы JOIN в SQL: -INNER JOIN (или просто JOIN): Возвращает строки, когда есть совпадение в обеих таблицах. Если совпадений нет, строка не возвращается; -LEFT JOIN (или LEFT OUTER JOIN): Возвращает все строки из левой таблицы и совпадающие строки из правой таблицы. Если в правой таблице нет совпадений, результатом является NULL; -RIGHT JOIN (или RIGHT OUTER JOIN): Возвращает все строки из правой таблицы и совпадающие строки из левой таблицы. Если в левой таблице нет совпадений, результатом является NULL; -FULL JOIN (или FULL OUTER JOIN): Возвращает строки, когда есть совпадение в одной из таблиц. То есть, он объединяет результаты LEFT и RIGHT JOIN; -CROSS JOIN: Возвращает декартово произведение строк из таблиц, участвующих в объединении. То есть, каждая строка из первой таблицы объединяется с каждой строкой из второй таблицы; -SELF JOIN: Это специальный случай, когда таблица объединяется сама с собой, как если бы она была двумя разными таблицами.

## CROSS JOIN

Оператор CROSS JOIN в PostgreSQL используется для выполнения декартова произведения строк из двух или более таблиц. ## UNION и объединение множества

UNION – это операции, которые позволяют объединить результаты двух или более запросов в один набор данных. Оператор UNION используется для объединения результатов двух или более запросов, с возможностью исключения дубликатов. Например, если есть два запроса, которые возвращают столбцы FirstName и LastName из таблиц Customers и Employees, соответственно, вы можно объединить их с помощью оператора UNION следующим образом:

Листинг 102. Пример объединения двух множеств SELECT FirstName, LastName FROM Customers UNION SELECT FirstName, LastName FROM Employees;

Результатом будет набор данных, содержащий уникальные комбинации имен и фамилий из обеих таблиц. Объединение множества, как операция, позволяет объединить результаты двух или более запросов, включая все строки из каждого запроса. Например, если есть два запроса, которые возвращают столбцы FirstName, LastName и AccountSum из таблиц Customers и Employees, соответственно, можно объединить их с помощью оператора UNION ALL следующим образом:

<u>Листинг 103. Пример объединения двух множеств без исключения дубликатов</u> SELECT FirstName, LastName, AccountSum FROM Customers UNION ALL SELECT FirstName, LastName, NULL AS AccountSum FROM Employees;

Результатом будет набор данных, содержащий все строки из обеих таблиц, где строки из таблицы Customers будут содержать значения из столбца AccountSum, а строки из таблицы Employees будут содержать NULL значения для столбца AccountSum. Объединение множества может быть полезным, когда нужно объединить данные из нескольких таблиц или запросов в один набор данных. Следует учесть, что в некоторых случаях, при объединении с использованием ключевого слова UNION, столбцы объединяемых таблицы должны совпадать по типам. Сделаем объединение результатов двух выборок. ## Группировка строк

## HAVING

Оператор HAVING используется для фильтрации результатов запроса, основываясь на условиях, применяемых к агрегатным функциям. Он работает подобно оператору WHERE, но применяется после оператора GROUP BY и фильтрует группы данных, а не отдельные строки. HAVING позволяет указывать условия, которые должны выполняться для групп данных, сгруппированных с помощью оператора GROUP BY. Это позволяет фильтровать группы данных на основе результатов агрегатных функций, таких как COUNT, SUM, AVG, MIN, MAX и других.

Листинг 111. Пример использования оператора HAVING SELECT column1, column2, COUNT(*) FROM table_name GROUP BY column1, column2 HAVING COUNT(*) > 10;

В этом примере группируются данные из таблицы table_name по столбцам column1 и column2 и вычисляется количество строк в каждой группе с помощью функции COUNT. Затем используется оператор HAVING для фильтрации групп данных, оставляя только те, у которых количество строк больше 10. Оператор HAVING может использоваться с различными условиями, такими как >, <, >=, <=, = и другими, а также с логическими операторами AND и OR для комбинирования условий.

Оконные функции в PostgreSQL позволяют выполнять вычисления на наборе строк, связанных с текущей строкой запроса. Оконные функции могут использоваться для вычисления сумм, средних значений, ранжирования строк и других операций, которые требуют доступа к данным внутри окна. Примеры оконных функций в PostgreSQL: -ROW_NUMBER: Возвращает порядковый номер текущей строки внутри окна. -RANK: Присваивает ранг текущей строки внутри окна на основе заданного порядка.

1) Выбор столбцов: в начале запроса SELECT указываются столбцы, данные из которых нужно извлечь. Можно выбрать все столбцы, используя символ *, или указать конкретные столбцы через запятую.

5) Фильтрация групп данных: с помощью ключевого слова HAVING можно задать условия, которым должны удовлетворять группы данных.

Подзапросы в SQL используются для выполнения вложенных запросов внутри основного запроса. Подзапросы могут быть использованы для различных целей, таких как фильтрация данных, связывание таблиц, вычисление агрегатных функций на подмножестве данных и других операций. ## Предикат IN

Предикат IN в SQL используется для проверки, соответствует ли значение любому значению в списке или подзапросе. Если значение соответствует хотя бы одному значению в списке или подзапросе, условие считается истинным. ## EXISTS

Предикат EXISTS в SQL используется для проверки существования результатов подзапроса. Он возвращает значение TRUE, если подзапрос возвращает хотя бы одну строку, и FALSE, если подзапрос не возвращает ни одной строки. EXISTS выполняет подзапрос и проверяет, есть ли результаты в подзапросе. Если подзапрос возвращает хотя бы одну строку, условие считается истинным

(TRUE). Если подзапрос не возвращает ни одной строки, условие считается ложным (FALSE).

Листинг 124. Пример использования предиката EXISTS SELECT column1, column2 FROM table_name WHERE EXISTS (SELECT * FROM another_table WHERE condition);

В этом примере мы выбираем значения из столбцов column1 и column2 из таблицы table_name, где существуют результаты в подзапросе. Подзапрос выбирает все строки из таблицы another_table, которые удовлетворяют определенному условию. EXISTS полезен, когда вам нужно проверить наличие данных в другой таблице или выполнить действия, основанные на результате подзапроса.

## ON CONFLICT

Ключевое слово ON CONFLICT используется в SQL для обработки конфликтов, которые могут возникнуть при выполнении операции вставки (INSERT) или обновления (UPDATE) данных в таблице. Оно позволяет определить, как обрабатывать конфликты, когда возникают дубликаты уникальных ключей или нарушения ограничений целостности. Вот как работает ON CONFLICT: -когда операция INSERT или UPDATE вызывает конфликт, например, из-за нарушения уникального ключа или ограничений целостности, ON CONFLICT задает дальнейшие действия.

-вы можете указать различные варианты действий, такие как выполнение альтернативной операции, обновление существующих строк или игнорирование конфликта. -действия ON CONFLICT могут быть определены для всей таблицы или для конкретных столбцов, имеющих уникальные индексы или ограничения.

Листинг 128. Пример использования ON CONFLICT INSERT INTO table_name (column1, column2) VALUES (value1, value2) ON CONFLICT (column1) DO UPDATE SET column2 = EXCLUDED.column2;

В этом примере мы выполняем операцию вставки (INSERT) в таблицу table_name. Если возникает конфликт по значению столбца column1, то с помощью ON CONFLICT мы выполняем операцию обновления (UPDATE), устанавливая значение столбца column2 равным значению из вставляемой строки (EXCLUDED.column2). ON CONFLICT позволяет более гибко управлять конфликтами данных и выбирать необходимые действия в зависимости от ситуации. Попробуем вставить в таблицу student данные, две строки которых уже совпадают по первичному ключу со строками, уже имеющимися в таблице. В исходной таблице уже имеются строки с id = 7 и 8.

## COPY

Команда COPY в PostgreSQL используется для копирования данных между таблицами и файлами в базе данных PostgreSQL. Она предоставляет возможность копировать данные из таблицы в файл (COPY TO) или из файла в таблицу (COPY FROM). Вот примеры использования команды COPY в PostgreSQL:

Листинг 134. Копирование данных из таблицы в файл COPY table_name TO 'path/to/file.csv' DELIMITER ',' CSV HEADER;

В этом примере данные из таблицы table_name копируются в файл file.csv с разделителем, в формате CSV. Заголовки столбцов также будут включены в файл.

Листинг 135. Копирование данных из файла в таблицу COPY table_name (column1, column2) FROM 'path/to/file.csv' DELIMITER ',' CSV HEADER;

В этом примере данные из файла file.csv с разделителем, в формате CSV копируются в таблицу table_name. Указаны только определенные столбцы column1 и column2, которые будут заполнены данными из файла. Операция COPY в PostgreSQL предоставляет различные опции, такие как разделитель, формат файла (CSV, текстовый и другие), наличие заголовков столбцов и другие. Опции могут быть указаны в команде COPY для настройки процесса копирования данных.

## TRUNCATE

TRUNCATE используется для быстрого удаления всех строк из таблицы без возможности отката операции и без запуска триггеров. Она позволяет освободить место на диске, занимаемое данными таблицы, и сбросить значения автоинкрементных столбцов.

<u>Листинг 136. Пример использования команды TRUNCATE в PostgreSQL</u> <u>TRUNCATE TABLE table_name;</u>

В этом примере все строки из таблицы table_name будут удалены. Структура таблицы, ее столбцы, ограничения и индексы остаются неизменными. Операция TRUNCATE выполняется быстрее, чем команда DELETE, так как она не сканирует таблицу, а просто освобождает занимаемое ею пространство на диске. Она также не записывает удаленные строки в журнал транзакций, что уменьшает нагрузку на систему. Однако, следует быть осторожным при использовании команды TRUNCATE, так как она не может быть отменена с помощью операции отката (ROLLBACK). Также обратите внимание, что TRUNCATE требует прав доступа к таблице.

## DELETE FROM

Команда DELETE FROM в PostgreSQL используется для удаления одной или нескольких строк из таблицы в базе данных. Она позволяет удалить данные, удовлетворяющие определенным условиям, из таблицы.

Листинг 137. Пример использования команды DELETE FROM в PostgreSQL DELETE FROM table_name WHERE condition;

В этом примере строки, удовлетворяющие условию condition, будут удалены из таблицы table_name. Условие может быть любым выражением, которое определяет, какие строки должны быть удалены. Например, DELETE FROM customers WHERE age > 30; удалит все строки из таблицы customers, где значение столбца age больше 30. Операция DELETE FROM также может быть использована без указания условия, что приведет к удалению всех строк из таблицы. Например, DELETE FROM table_name; удалит все строки из таблицы table_name. Важно отметить, что DELETE FROM может быть отменена с помощью операции отката (ROLLBACK), если она выполняется в рамках транзакции.

## DELETE USING

Команда DELETE USING позволяет удалять строки из одной таблицы на основе данных из другой таблицы. Это полезно, когда вы хотите удалить строки, которые соответствуют определенным критериям, основанным на данных в другой таблице.

## Описание выполнения работы

ER-модель (Entity-Relationship model или ER-модель) — это концептуальная модель данных, которая используется для описания информационных систем. Она была предложена в 1976 году и с тех пор активно используется в области проектирования баз данных.

## Компоненты ER-модели

ER-модель включает в себя следующие основные компоненты: -Сущности (Entities): Это основные объекты или концепции, которые имеют значение в контексте информационной системы. Например, в базе данных магазина сущностями могут быть «Продукт», «Клиент», «Заказ» и т.д. -Атрибуты (Attributes): Это характеристики или свойства сущностей. Например, для сущности «Продукт» атрибутами могут быть «Название», «Цена», «Категория» и т.д. -Связи (Relationships): Это отношения между сущностями. Например, «Клиент» может быть связан с «Заказом» отношением «сделал заказ». ER-модель используется для визуализации и организации данных в информационной системе. Она помогает разработчикам и пользователям лучше понять структуру данных и отношения между различными элементами данных.

С помощью ER-модели можно проектировать структуру базы данных, определять, какие данные будут храниться, и как они будут взаимодействовать друг с другом. Это особенно полезно на этапах проектирования и анализа системы, когда необходимо четко определить требования к данным и их структуре. В общем, ER-модель – это мощный инструмент для проектирования и анализа информационных систем, который помогает обеспечить эффективное и организованное управление данными. ## Связи между таблицами в базе данных

В базах данных существуют три основных типа связей между таблицами: -один к одному (One-to-One): каждая запись в первой таблице соответствует одной записи во второй таблице и наоборот. Этот тип связи часто используется, когда две таблицы имеют прямую и уникальную связь друг с другом; -один ко многим (One-to-Many): одна запись в первой таблице может соответствовать нескольким записям во второй таблице, но каждая запись во второй таблице соответствует только одной записи в первой таблице. Это самый распространенный тип связи в базах данных; -многие ко многим (Many-to-Many): одна запись в первой таблице может соответствовать нескольким записям во второй таблице, и наоборот, одна запись во второй таблице может соответствовать нескольким записям в первой таблице. Этот тип связи обычно реализуется с помощью вспомогательной таблицы, которая содержит внешние ключи обеих связанных таблиц. Связи между таблицами устанавливаются с помощью внешних ключей (Foreign Keys), которые указывают на связанные записи в других таблицах. Это позволяет обеспечить целостность данных и избежать дублирования информации. В SQL для работы со связями между таблицами используются операторы JOIN, такие как INNER JOIN, LEFT JOIN, RIGHT JOIN и другие. Они позволяют объединять данные из разных таблиц на основе заданных условий.

## Описание выполнения работы

Индексы в PostgreSQL используются для ускорения операций поиска и извлечения данных из базы данных. Они работают аналогично индексам в книге, позволяя быстро найти нужную информацию, не просматривая все страницы. Основные цели использования индексов в PostgreSQL: -ускорение запросов: Индексы позволяют существенно ускорить выполнение запросов, особенно при работе с большими объемами данных. Без индексов, для выполнения запроса SELECT, например, PostgreSQL должен просмотреть каждую строку в таблице, чтобы определить, удовлетворяет ли она условиям запроса. Если же есть индекс, PostgreSQL может быстро найти нужные строки. -обеспечение уникальности данных: Индексы также используются для обеспечения уникальности данных в таблицах. Например, можно создать уникальный индекс на столбец email, чтобы гарантировать, что каждый адрес электронной почты в таблице будет уникальным. В PostgreSQL поддерживаются различные типы индексов, включая B-Tree, Hash, GiST, SP-GiST и GIN. Выбор типа индекса зависит от конкретных требований и характеристик данных. Создание индексов в PostgreSQL осуществляется с помощью команды CREATE INDEX. Например, следующий запрос создает индекс на столбец email в таблице customers:

Листинг 145. Пример создания индекса CREATE INDEX idx_email ON customers (email);

Важно помнить, что, хотя индексы ускоряют чтение данных, они могут замедлить операции вставки, обновления и удаления, так как при каждой такой операции индекс также должен быть обновлен. Кроме того, индексы занимают дополнительное место на диске. Поэтому важно найти баланс между количеством и типами индексов в зависимости от конкретных требований к приложению. При выполнении запроса, например, SELECT * FROM table_name WHERE column_name = 'value', база данных сначала проверяет, есть ли индекс для столбца column_name. Если индекс существует, база данных использует его для быстрого нахождения всех строк, где column_name равно 'value', вместо того чтобы просматривать каждую строку в таблице. В PostgreSQL индексы могут быть использованы не только для операций сравнения, но и для операций LIKE, если поиск ведется по началу строки. Однако стоит помнить, что создание и поддержание индексов требует дополнительных ресурсов. Поэтому важно найти баланс между количеством и типами индексов в зависимости от конкретных требований к приложению. ## Уникальные индексы

Создание уникальных индексов в PostgreSQL позволяет гарантировать уникальность значений в указанных столбцах таблицы. Уникальный индекс предотвращает вставку или обновление данных, которые нарушают уникальность.

Для создания уникального индекса в PostgreSQL можно использовать команду CREATE UNIQUE INDEX. Например, следующий запрос создает уникальный индекс на столбец email в таблице users:

Листинг 152. Создание уникального индекса CREATE UNIQUE INDEX idx_email ON users (email);

После создания уникального индекса, база данных будет автоматически проверять уникальность значений в указанных столбцах при выполнении операций вставки или обновления данных. Если попытаться вставить или обновить данные, которые нарушают уникальность, PostgreSQL выдаст ошибку. Уникальные индексы особенно полезны для столбцов, которые должны содержать уникальные значения, такие как идентификаторы, адреса электронной почты или имена пользователей.

## Описание выполнения работы

Транзакция в PostgreSQL – это логическая единица работы, которая состоит из одной или нескольких операций базы данных. Она представляет собой последовательность операций, которые должны быть выполнены как единое целое. Если все операции в транзакции выполняются успешно, то изменения сохраняются в базе данных. В случае возникновения ошибки или отката транзакции, все изменения отменяются и база данных остается в прежнем состоянии. Транзакции обеспечивают ACID-свойства, что означает следующее: -атомарность (Atomicity): Транзакция считается успешно выполненной только в том случае, если все ее операции завершаются успешно. Если хотя бы одна операция не может быть выполнена, то все изменения отменяются. -согласованность (Consistency): Транзакция должна приводить базу данных из одного согласованного состояния в другое согласованное состояние. Это означает, что все ограничения целостности должны быть соблюдены во время выполнения транзакции. -изолированность (Isolation): Каждая транзакция должна быть изолирована от других транзакций, выполняющихся параллельно. Это гарантирует, что результаты одной транзакции не будут видны другим транзакциям до ее завершения. -долговечность (Durability): После успешного завершения транзакции ее изменения должны быть сохранены даже в случае сбоя системы или отключения питания.

Транзакции могут быть начаты с помощью команды BEGIN и завершены с помощью команды COMMIT. Если необходимо отменить все изменения в рамках транзакции, можно использовать команду ROLLBACK.

<u>Листинг 156. Пример использования транзакции в PostgreSQL</u> BEGIN; UPDATE people SET name = 'Ivan' WHERE id = 1; UPDATE people SET lastname = 'Gray' WHERE id = 10; <u>COMMIT;</u>

В этом примере выполняются две операции обновления данных в таблице «people». Если обе операции выполняются успешно, изменения сохраняются в базе данных с помощью команды COMMIT. Если возникает ошибка или требуется отменить изменения, можно использовать команду ROLLBACK.

## Многоверсионная модель данных

Многоверсионная модель данных (MVCC) – это метод управления параллельным доступом к данным, который позволяет одновременно выполнять транзакции без блокировки данных. В MVCC каждая транзакция видит свой собственную «копию» данных на момент начала транзакции, что позволяет избежать блокировок и конфликтов при одновременном доступе к данным. Работа транзакций основана на MVCC, принципы которой следующие: -при начале каждой транзакции создается снимок данных, который отражает состояние базы данных на момент начала транзакции. Этот снимок используется для чтения данных в течение всей транзакции. -когда данные изменяются, СУБД создает новую версию строки, а старая версия остается неизменной. Это позволяет каждой транзакции видеть свою версию данных, не блокируя другие транзакции. -если две транзакции пытаются изменить одну и ту же строку, PostgreSQL использует проверку времени жизни транзакции (transaction ID) для определения, какая транзакция должна быть выполнена первой. Это позволяет избежать конфликтов и обеспечивает согласованность данных. -происходит периодическое удаление устаревших версий строк, чтобы освободить место в базе. Этот процесс называется «вакуумированием» и позволяет поддерживать производительность базы данных.

MVCC обеспечивает высокую производительность и параллелизм при одновременном доступе. Он позволяет выполнять множество транзакций одновременно, минимизируя блокировки и повышая эффективность работы с базой данных. В PostgreSQL существуют несколько уровней изоляции транзакций: -Read Uncommitted (Чтение неподтвержденных данных): Этот уровень изоляции позволяет транзакциям читать данные, которые были изменены другими транзакциями, но еще не подтверждены. Это самый низкий уровень изоляции и может привести к проблемам с целостностью данных. -Read Committed (Чтение подтвержденных данных): Этот уровень изоляции гарантирует, что транзакции будут видеть только подтвержденные изменения данных. Транзакции не будут видеть изменения, которые еще не были подтверждены другими транзакциями. -Repeatable Read (Повторяемое чтение): Этот уровень изоляции гарантирует, что транзакции будут видеть одинаковые данные при повторном чтении в рамках той же транзакции. Другие транзакции не смогут изменять данные, которые были прочитаны в рамках текущей транзакции. -Serializable (Сериализуемость): Этот уровень изоляции обеспечивает самый высокий уровень изоляции. Он гарантирует, что транзакции будут работать так, как если бы они выполнялись последовательно, без взаимного влияния друг на друга. Это достигается блокировкой данных таким образом, чтобы предотвратить конфликты между транзакциями. Каждый уровень изоляции имеет свои особенности и подходит для разных сценариев использования. По умолчанию в PostgreSQL используется уровень изоляции Read Committed. Но ситуация усложняется наличием неопределенного поведения при работе с транзакциями или при фиксации изменений в них. Это недопустимое поведение называют аномалией или аномальным поведением. Подробную информацию об аномалиях и механизмах их работы можно посмотреть в [4].

## READ COMMITTED

Уровень изоляции Read Committed в PostgreSQL означает, что транзакции будут видеть только подтвержденные изменения данных и если другая транзакция вносит изменения в данные, эти изменения не будут видны другим транзакциям до тех пор, пока изменения не будут подтверждены.

Уровень изоляции Read Committed обеспечивает более высокую степень изоляции, чем Read Uncommitted, но не гарантирует повторяемость чтения (non- repeatable reads) или предотвращение фантомных строк (phantom reads). В PostgreSQL уровень изоляции Read Committed является уровнем изоляции по умолчанию.

## REPEATABLE READ

Уровень изоляции Repeatable Read в PostgreSQL обеспечивает более высокую степень изоляции, чем Read Committed с некоторыми особенностями: -при использовании уровня изоляции Repeatable Read транзакция видит снимок данных, созданный в начале транзакции. Это означает, что если транзакция выполняет чтение данных, то при повторном чтении эти данные будут такими же, как и в начале транзакции, даже если другие транзакции вносили изменения в эти данные. -Repeatable Read блокирует строки данных, прочитанные в рамках транзакции, чтобы предотвратить изменения этих строк другими транзакциями. Это гарантирует, что данные, прочитанные в рамках транзакции, останутся неизменными до ее завершения. -этот уровень изоляции предотвращает фантомные строки (phantom reads), которые возникают, когда транзакция выполняет запрос, возвращающий набор строк, а затем другая транзакция вставляет или удаляет строки, которые соответствуют условиям запроса. В уровне изоляции Repeatable Read такие изменения не будут видны в рамках текущей транзакции. -уровень изоляции Repeatable Read не позволяет транзакциям изменять или удалять существующие строки данных, прочитанные в рамках транзакции. Однако, другие транзакции могут вставлять новые строки данных, которые соответствуют условиям запроса текущей транзакции.

Важно отметить, что уровень изоляции Repeatable Read может привести к блокировкам и увеличению использования ресурсов, поскольку строки данных блокируются до завершения транзакции. Исследуем работу этого уровня изоляции на практике. Начнем транзакцию с уровнем REPEATABLE READ.

## Описание выполнения работы

Функции – это именованные блоки кода, которые могут принимать аргументы, выполнять определенные операции и возвращать результаты. Они используются для организации и структурирования логики обработки данных в базе данных. Некоторые основные аспекты работы с функциями: -функции могут быть созданы с использованием языка SQL или PL/pgSQL (язык хранимых процедур PostgreSQL). SQL-функции позволяют выполнять простые операции, такие как выборка данных или выполнение вычислений. PL/pgSQL-функции предоставляют более широкие возможности, включая условные операторы, циклы и переменные. -функции могут принимать аргументы, которые передаются им при вызове. Аргументы могут быть обязательными или необязательными, а также могут иметь различные типы данных, такие как целые числа, строки или даты. -возвращаемые значения: Функции могут возвращать результаты, которые могут быть различных типов данных. Например, функция может возвращать целое число, строку или таблицу. -хранимые процедуры: В PostgreSQL также поддерживаются хранимые процедуры, которые являются особым типом функций. Хранимые процедуры могут выполняться на стороне сервера базы данных и могут

использоваться для выполнения сложных операций, включая манипуляции с данными и управление транзакциями. -использование функций: Функции могут быть вызваны из SQL-запросов или из других функций. Они могут использоваться для выполнения различных операций, таких как фильтрация данных, агрегация, преобразование данных и многое другое. Функции предоставляют мощный инструмент для организации и управления логикой обработки данных в базе данных. Они позволяют создавать модульный и переиспользуемый код, что способствует улучшению производительности и обслуживаемости базы данных. Функции в основном используются для упрощения решения задач зачет их декомпозиции. В ней описан четкий интерфейс с реализацией и используются для выполнения различных операций и обработки данных. Они могут быть написаны на различных языках программирования, включая PL/pgSQL, SQL, Python и C, что позволяет разработчикам использовать мощные библиотеки и инструменты для работы с данными. Вот некоторые примеры того, для чего могут быть использованы функции: -для обработки и преобразования данных; -для выполнения сложных операций, которые не могут быть выполнены с помощью стандартных SQL-запросов. Например, они могут быть использованы для выполнения сложных алгоритмов или для работы с данными, которые требуют специальной обработки; -для расширения функциональности базы данных, создания новых типов данных, операторов или функций, которые не предоставляются PostgreSQL по умолчанию; -для интеграции PostgreSQL с другими системами и взаимодействия с внешними API, системами управления данными или другими базами данных; -для оптимизации производительности базы данных. Например, они могут быть использованы для создания индексов или для выполнения операций, которые могут быть оптимизированы с помощью функций. Важно отметить, что использование функций требует знания и понимания языка программирования, на котором они написаны, а также понимания структуры и функционирования базы данных.

## IN, OUT и INOUT в функциях

Функции могут иметь параметры различных типов: IN, OUT и INOUT. Эти типы определяют поведение параметров в функции. -IN: Это наиболее общий тип параметра, который используется в функциях. Параметры IN используются для передачи значений в функцию. Если вы не указываете тип параметра явно, он по умолчанию считается параметром IN. -OUT: Параметры OUT используются для возврата значений из функции. PostgreSQL поддерживает параметры OUT начиная с версии 8.1. Они позволяют функции возвращать несколько значений, что может быть весьма полезно в некоторых ситуациях. -INOUT: Параметры INOUT являются комбинацией параметров IN и OUT. Они могут быть использованы для передачи значений в функцию и возврата значений из функции. Это можно задействовать, когда вам нужно изменить значение параметра внутри функции и вернуть его обратно. Важно отметить, что использование параметров OUT и INOUT может усложнить понимание логики программы, поскольку они перемещают входные переменные из оператора SELECT в оператор INTO. Тем не менее, они могут быть полезны в некоторых ситуациях, когда вам нужно вернуть несколько значений из функции или изменить значение параметра внутри функции.

## Описание выполнения работы

Процедуры – это блоки кода, которые можно вызывать из программы или другой процедуры для выполнения определенной задачи. Они похожи на функции, но есть несколько ключевых различий. В PostgreSQL процедуры были введены в версии 11. Они позволяют выполнять транзакции внутри себя, что раньше было невозможно с функциями. Процедуры не возвращают значения, в отличие от функций, которые могут возвращать значение. Создание процедуры осуществляется с помощью команды CREATE PROCEDURE. Эта команда позволяет определить имя процедуры, параметры и тело процедуры. В теле процедуры можно использовать SQL-запросы и другие операторы для работы с данными.

<u>Листинг 194. Пример создания процедуры</u> CREATE OR REPLACE PROCEDURE my_procedure() LANGUAGE plpgsql AS $$ BEGIN --здесь ваш SQL код END; <u>$$;</u>

Также можно изменить существующую процедуру с помощью команды ALTER PROCEDURE. Важно отметить, что процедуры могут быть написаны на различных языках, включая PL/pgSQL и другие языки, поддерживаемые PostgreSQL. Процедуры могут быть полезны для выполнения регулярных задач, автоматизации операций и упрощения сложных запросов. Они также могут помочь улучшить производительность, поскольку позволяют базе данных компилировать и оптимизировать код процедуры один раз, а затем повторно использовать его. Функции не могут управлять транзакциями. Функции вызываются в контексте какого-либо выражения, которое вычисляется как часть уже начатого оператора в уже начатой транзакции. Нельзя завершить транзакцию и начать новую «посередине» выполнения оператора. Процедуры, как и функции, тоже могут возвращать результат, если необходимо. К сожалению, процедуры, написанные на языке SQL, лишены возможности использовать команды COMMIT и ROLLBACK, хотя те из них, что оформлены в новом стиле стандарта SQL, вероятно смогут это делать в будущем. Функции и процедуры имеют общее пространство имен и вместе называются подпрограммами (routine).

Для более глубокого понимания основ авторы рекомендуют продолжить изучение технических аспектов с помощью специальной профессиональной литературы.
